# Forráskód-alapú biztonsági ellenőrzés

Az ellenőrzés dátuma 2026. november 25. A hatókör a MunkaCash forráskódja, a verziózott fejlesztői konfiguráció és a főbb csomagok nyilvános biztonsági közleményei.

| Terület                          | Eredmény                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fejlesztői szolgáltatások        | A Sail által korábban minden hálózati interfészen közzétett portok most csak a helyi gépen elérhetők. A Vite+ 1.4.0 érintett a hálózatra kitett fejlesztői kiszolgálót érintő hibában. A zárolt fejlesztői csomagot a javított Vite+ 1.5.1-re frissítettük. [Gyártói közlemény](https://github.com/vitejs/vite/security/advisories/GHSA-p4f5-76q4-ffq7)                                                                                                           |
| Jogosultság és céges elkülönítés | A céges útvonalak bejelentkezést és megerősített e-mail-címet, a céges műveletek aktív tagságot igényelnek. A CSV-export és a lezárás a tulajdonoshoz kötött. A törlés kiszolgálói parancs, amely ellenőrzi a cég állapotát és az export határidejét. [OWASP útmutató](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)                                                                                                             |
| Válaszok és import               | Az üzleti oldalak sikeres GET-válaszai most `private, no-store` szabályt kapnak. Az export eleve tárolást tiltó fejlécet használ, és semlegesíti a táblázatkezelőben képletként értelmezhető cellakezdeteket. Az import korlátozza a fájlméretet és a sorszámot, az előnézetet céghez és feltöltőhöz köti.                                                                                                                                                        |
| Hitelesítés és küldés            | A webes űrlapok a Laravel CSRF-middleware-ét használják. A belépés, a kétlépcsős ellenőrzés és a passkey műveletek forgalomkorlátot kapnak. A tesztküldés helyi vagy tesztkörnyezetet és `.test` címzettet igényel. A dolgozó küldés előtt ismét ellenőrzi a céges állapotot.                                                                                                                                                                                     |
| Csomagok és titkok               | A zárolt Laravel 13.43.0 tartalmazza az ellenőrzött validációs javítást. A vizsgált React Server Components csomagok nem szerepelnek a lockfájlban. A jelenlegi fájllistában csak a titkok nélküli `.env.example` környezeti sablon szerepel. [Laravel-közlemény](https://github.com/laravel/framework/security/advisories/GHSA-cq3g-fj94-c8p3) · [React-közlemény](https://react.dev/blog/2025/12/03/critical-security-vulnerability-in-react-server-components) |

## Telepített környezet

A forráskód nem igazolja a tényleges telepítés TLS-beállításait, a publikus portokat, a dokumentumgyökeret, a sütik éles konfigurációját vagy a mentések elérését. Ezek ellenőrzéséhez a staging környezet telepítési beállításai szükségesek. A teljes tranzitív függőségi fa és az élő végpontok felülvizsgálata nyitott. Az npm audit futtatását megállította a külső csomagadat-továbbítás jóváhagyási ellenőrzése.
